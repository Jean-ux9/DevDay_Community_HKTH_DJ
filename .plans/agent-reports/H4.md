## What changed

| File | Change |
|---|---|
| `overlay/src/renderer/screens/ConfirmScreen.tsx` | Each `confirm_request.details` line renders verbatim (`textContent` equals the line); a short leading `Label:` (e.g. `To:`, `Subject:`, `Body:`) is emphasised; line breaks kept (`white-space: pre-wrap`). Long details get smaller type (>240 chars → 26 px, >600 → 20 px) and the body ends above CONFIRM (`bottom: 316px`) instead of running under it, with keyboard/mouse scroll as a caregiver fallback. `aria-describedby` points at the details. New optional `onAnswer(confirmed, sent)`, called for CONFIRM, CANCEL and the 60 s timeout. Positions, dwell variants, timeout and `respondConfirm` behaviour unchanged. |
| `overlay/src/renderer/App.tsx` | Remembers the task whose confirm the user actually approved (not a `demo_noop`). That task's `task_result` is shown by `ApprovedOutcome` instead of `ResultCards`: `ok:true` → "Handed to the app" + "The app accepted it. Delivery is not confirmed." (no `is-done` glow); `ok:false` → "Not confirmed" + "It may have gone through. Check before trying again." (never "Not done"). The agent's summary is shown as written. Cancelled/timed-out/other tasks keep the existing `ResultCards`. Back/STOP is now rendered whenever a task, confirm, choice or pending select is active, even if the idle screen state was `recenter`. |
| `overlay/src/renderer/screens/ConfirmScreen.test.ts` | Exact-text, label, line-break, long-content, aria, Cancel/timeout `onAnswer`, and "answer still sent without a callback" tests. |
| `overlay/src/renderer/ActionFlow.test.ts` (new) | App-level flow with session fakes: confirm shows recipient/content exactly with Cancel + STOP gaze targets; STOP during confirm sends `stop('gaze')` and no confirm answer; progress pill shows the agent's step message; Cancel → `respondConfirm(false)` → "Not done"; approved + ok → no "Done"/glow; approved + failure/unknown → "Not confirmed"; demo no-op stays "Done"; approval is per task; errors visible on the status line. |

Progress itself already worked through `task_status.message` in the status pill; no change there.
