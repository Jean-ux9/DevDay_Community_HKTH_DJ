## Mail implementation and evidence

[Apple documents creation and sending through Mail scripting](https://support.apple.com/guide/mail/automate-mail-tasks-mlhlp1120/mac).
[AppleScript command documentation](https://developer.apple.com/library/archive/documentation/AppleScript/Conceptual/AppleScriptLangGuide/reference/ASLR_cmds.html)
describes application commands and variable/object references.
[PyXA's Mail scripting bridge implementation](https://github.com/SKaplanOfficial/PyXA/blob/main/PyXA/apps/Mail.py)
provides source evidence for account `emailAddresses`/`enabled`, outgoing-message
`sender`/`content`/`messageSignature`, and boolean `send` on the retained object.
This is implementation evidence, not an Apple guarantee for the demo macOS build.
The shipped script
uses only Mail scripting terms: `make new outgoing message`, its exact returned
object, one `to recipient`, `sender`, `subject`, `content`, signature clearing and
`send newDraft`. No AX/UI scripting, activation, front window selection, inbox
reads or scan of existing drafts. Matching the supplied sender against Mail's
configured accounts occurs only in the human-approved execute script; it returns
no account data. Missing, disabled or multiply matched sender accounts fail before
draft creation. It does not discover a sender for the proposal.

Prepare constructs only a frozen H1 payload. Execute invokes the static
`mail_send.applescript` file through `/usr/bin/osascript`, passing all values as
separate argv data. It clears the signature, sets exact body content, and checks
only the newly created object's single To, empty Cc/Bcc, sender and subject.
Mail's sender readback must exactly match the configured value; formatting or
unsupported-account differences fail closed before send. `dispatchStarted` is
set immediately before `send newDraft`; only allowlisted static phase markers
can establish a pre-send failure. Errors during send, false/absent acknowledgement,
nonzero process exit and lost output are unknown. No parsing of native error text.

Static source inspection checks the retained draft identity; **no AppleScript
compilation or native Mail behavior was tested**. The script does not read body
back as supposed evidence. Exact UTF-8 content is verified at the fake subprocess
boundary, not as MIME/received-message bytes. Mail may apply its own formatting.
A pre-send failure may leave its own unsent draft; there is deliberately no
draft sweep, deletion or retry. A timeout may leave a draft or a submitted mail.

The optional adapter calls only standard `imsg send`. Missing executable produces
`failed/missing_tool`; no installation or account/tool discovery is attempted.
Only exit 0 plus exactly `{"status":"sent"}` yields acknowledgement. Other
CLI outcomes, including permission/account diagnostic text, are conservatively
unknown because a generic CLI failure does not establish non-submission.
The adapter never parses error prose, output handles or raw stderr.

groups, history or local receipt verification. Standard imsg chooses the existing

## Bounds, privacy and human validation

Subprocesses use argument vectors, no shell, a new process session, DEVNULL stdin
and stderr, and a 1024-byte stdout cap. No raw stdout/stderr goes into results or
logs. Default operation deadline is 20 seconds; cleanup sends TERM, then KILL to
the owned group and reaps the child. Child acquisition is shielded through
repeated cancellation; a late spawn is cleaned up rather than abandoned. OS
process creation/reaping cannot safely be abandoned, so ownership/cleanup may
outlast that deadline if the OS itself stalls. STOP dispatch/UI responsiveness
must not depend on completion of this ownership cleanup. Tests use injected fake
processes and signals only. Content uses argv, so same-user process inspection
may see it while running; this is not encrypted transport/storage. No provider
payload is persisted by H3.

Bodies are bounded to 32768 UTF-8 bytes, Mail subjects to 4096 bytes; NUL/invalid
Unicode rejected, subject/header controls rejected. Accepted text is not trimmed,
escaped, normalized or rewritten. Address validation intentionally accepts only
a narrow addr-spec subset; unsupported legitimate formats fail closed.

Per device, humans must independently verify Mail is configured with the approved
sender/account and verify Automation permission for the actual responsible
terminal/packaged app. Mail script compilation, signature clearing, sender
readback, one-recipient identity and received content remain human checks. For
Messages, humans must provide a compatible standard imsg build on the launcher's
PATH, a signed-in approved iMessage service and Automation permission. No Full
Disk Access/Contacts/SIP change is requested by this adapter. These prerequisites
are not established by another laptop's setup or by the fake tests.

First integrate H1 wiring and H5 fake Cancel/approval/STOP tests. Human tests then
begin with no-send proposal/Cancel. A single controlled actual send requires
separate explicit human authorization. No actual send is authorized for coding
agents. No native, live API, app activation, screenshot, clipboard, AX, input,
permission change or live provider call was performed here.
