1. PROVIDER API (for the server/loop and rehearsal owners)
----------------------------------------------------------
Selector: environment variable GAZE_DEMO_CONFIG = absolute path to a private manifest.
  - Unset or "" -> selected() returns None -> every existing public-fixture path is
    unchanged (fixtures/demo_profile.json, default ProfileStore, agent/replay/cache).
  - Set -> DEMO_MODE=1 is required in the same environment (checked before any read).
  - Recommendation: export it in the shell, not in .env. rehearse.py reads its own
    environment, while the real agent child also receives --env-file .env. A mismatch
    fails closed because the exact persona check refuses it.

Module agent/gaze_agent/demo_config.py. Imports only the standard library and reads
no file on import (tested with `python -I -S` and an audit hook). jsonschema is
imported only during validation; the harness script environment already has it.
  SELECTOR_ENV = "GAZE_DEMO_CONFIG";  MANIFEST_FORMAT = "gaze-private-demo/1"
  REPO_ROOT, PUBLIC_PERSONA_PATH, USER_DATA_DIR (same values as profile.DEMO_PROFILE/DATA_DIR)
  class DemoConfigError(ValueError)   messages name the field and reason; never paths/handles
  selected(environ: Mapping | None = None) -> PrivateDemoConfig | None
  load_manifest(path) -> PrivateDemoConfig
  parse_manifest(data, *, manifest_path=None) -> PrivateDemoConfig
  PrivateDemoConfig (frozen; repr shows only config_id + fingerprint prefix):
    .config_id: str     .data_dir: Path     .cache_dir: Path     (both resolved)
    .fingerprint: str   sha256 over format, config_id, persona and approved recipients
                        (excludes the storage paths)
    .recording_dir      cache_dir / f"{config_id}-{fingerprint[:16]}"
    .persona() -> dict              fresh copy, in protocol Profile key order
    .approved_contacts() -> dict[str, list[str]]   fresh copy; same format as the loop's demo_contacts
    .check_profile(profile) -> None raises DemoConfigError if any alias or handle is unapproved

agent/gaze_agent/profile.py:
  ProfileStore(directory=DATA_DIR, *, demo=None, demo_profile=DEMO_PROFILE, demo_config=None)
  ProfileStore.for_demo_config(config_or_None) -> ProfileStore
      None    -> ProfileStore()   (unchanged default)
      private -> ProfileStore(config.data_dir, demo=True, demo_config=config)
  ProfileStore.approved_contacts() -> dict   Send allowlist. Private: the manifest's list.
      Public demo: the fixture's contacts (exactly what server.start() reads today).
      Not demo: {}. Never derived from the editable active profile.
  Private store: the first load seeds profile.json in data_dir from the persona.
      load_profile()/update_profile() raise DemoConfigError (a ValueError) when the
      stored or edited contacts include an unapproved alias or handle. Nothing is saved.
  load_profile() -> ProfileStore.for_demo_config(demo_config.selected()).load_profile()

agent/gaze_agent/llm.py (complete() signature and real Responses client unchanged):
  REPLAY=off: unaffected by the selector.
  REPLAY=record|replay: resolves selected(). A selection error becomes LLMError before
  any client or file. A private config reads and writes only recording_dir (0700 dirs,
  0600 files). The recording guard compares the active profile, through load_profile()
  (same configuration), with config.persona(), and prompt profile_summary/profile_style
  with that persona. The public behavior and its messages are unchanged.

Manifest semantics:
  - Exactly these fields; an unknown or missing field is rejected.
  - "persona" must validate against protocol/messages.schema.json $defs/Profile.
  - "approved_recipients" must list EXACTLY persona.contacts (same aliases, same handles,
    order irrelevant). Empty, padded, control-character, over-long, duplicate
    (case-insensitive) or shared handles/aliases are rejected.
  - The manifest, data_dir and cache_dir must be absolute and outside this checkout and
    every Git work tree (any ancestor with .git; symlinks are resolved). They must not
    be /, $HOME, or overlap ~/Library/Application Support/GazeCopilot, and data_dir and
    cache_dir must not overlap each other. The manifest must not be inside either
    directory, must be owned by the user, must not be group/world-writable and must be
    at most 64 KiB of strict JSON (no duplicate keys, no NaN).

9. PROMPT CHANGES (P06) - HONEST RECORDING REFRESH
--------------------------------------------------
The cache key covers the template body, model, effort, normalized vars, tools and input,
so any prompts/*.md body change makes the affected entries miss.
  - Public synthetic set: test_shipped_demo_cache_replays_without_api_or_active_profile
    and the check_* replays will fail until a human authorizes live calls and runs
    `check_planner.py record` / `check_prompts.py record`. Review the new
    planner_expected.json/prompts_expected.json and commit the new cache files.
  - Private namespaces: recordings for changed prompts miss as well; re-record them
    through the real flows after the consumer edits and human authorization.
  - A changed persona or allowlist gets a new namespace by design and needs new recordings.
Never rename, rekey or edit old responses so that they match new prompts.
